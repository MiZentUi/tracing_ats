# Conventional Commits

Применяй этот скилл каждый раз, когда предлагаешь сообщение коммита, проверяешь историю
или исправляешь уже существующее сообщение.

Полная спецификация — `references/conventional-commits-1.0.0.md`.

## Формат

```text
<type>[optional scope][!]: <description>

[optional body]

[optional footer(s)]
```

- `type` — обязательный, английский, в нижнем регистре.
- `scope` — необязательный, английский, в нижнем регистре, в скобках.
- `!` — ставится перед двоеточием, если коммит ломает обратную совместимость.
- После двоеточия обязателен пробел.
- `description` — на русском, в повелительном наклонении, без точки в конце,
  желательно до 72 символов.
- `body` — необязательный, на русском, через пустую строку после description.
  Объясняет «почему», а не «что»; строки до 72 символов.
- `footer(s)` — через пустую строку после body или description, формат `<token>: <value>`.

## Типы

| Тип | Когда использовать | SemVer |
|---|---|---|
| `feat` | Новая функциональность | MINOR |
| `fix` | Исправление ошибки | PATCH |
| `build` | Сборка, зависимости, Maven/Docker | — |
| `chore` | Рутина, конфиги, `.gitignore` | — |
| `ci` | CI/CD и пайплайны | — |
| `docs` | Документация, README, ADR | — |
| `style` | Форматирование без изменения логики | — |
| `refactor` | Рефакторинг без новой функциональности и исправлений | — |
| `perf` | Улучшение производительности | — |
| `test` | Тесты и тестовые данные | — |
| `revert` | Откат предыдущего коммита | — |

Другие типы не используй. Если изменение подходит под несколько типов, раздели его на
несколько коммитов.

## Scope проекта

Используй один из scope, если он помогает понять область изменения:

- `resume-service`, `vacancy-service` — Java-сервисы;
- `migrations` — Liquibase-миграции и джоба миграций;
- `backend` — общий родительский POM и сквозные изменения Java-контура;
- `infra` — `docker-compose`, окружение, mock-LLM;
- `contracts` — `openapi.yaml`, gRPC-прото и JSON Schema;
- `scoring-service` — Python-сервис в `backend/scoring-service`;
- `ml-trainer` — Python-контур офлайн-обучения;
- `frontend` — Vue-приложение;
- `docs`, `agents` — документация и инструкции агента.

Scope необязателен. Не придумывай новый scope, если хватает существующего.

## Breaking changes

Ломающее изменение обозначается одним из двух способов:

```text
feat(contracts)!: заменить поле score на score_pre

BREAKING CHANGE: клиенты должны читать score_pre и score_final раздельно
```

- `!` после типа или scope обязателен, если меняется публичный контракт,
  формат артефакта, схема БД или поведение API.
- `BREAKING CHANGE:` пишется заглавными буквами и объясняет миграцию.
- Ломающим может быть коммит любого типа, не только `feat` и `fix`.

## Обязательные правила проекта

1. **Один коммит — одна смысловая единица.** Не смешивай рефакторинг, миграцию и фичу.
2. **Не логируй PII и секреты** в сообщении коммита: ни имён, ни контактов, ни токенов,
   ни текстов резюме.
3. **Контракт и реализация — вместе**, если контракт менялся. Это отражай в scope.
4. **Не выдумывай факты.** В body только то, что реально сделано и проверено.
5. **Не пиши «fix», если это новая функциональность**, и наоборот.
6. **Не используй прошедшее время** в description: `добавить`, `исправить`, `вынести`,
   а не `добавил`, `исправил`, `вынес`.
7. **Не заканчивай description точкой.**
8. **Ссылки на задачи и PR** — только в footer: `Refs: #123`, `Closes: #45`.

## Примеры

```text
feat(vacancy-service): добавить шаблон требований из текста вакансии
```

```text
fix(resume-service): отбрасывать цитату, которой нет в обезличенном тексте

Проверка подстроки выполняется до расчёта покрытия, поэтому
неподтверждённая цитата больше не завышает c_r.

Refs: #128
```

```text
build(backend): перевести сборку на Maven multi-module

BREAKING CHANGE: модули resume-service и vacancy-service собираются
из backend/pom.xml, старый build.gradle удалён
```

```text
docs(agents): описать конвенцию коммитов в скилле
```

```text
revert: откатить преждевременную активацию профиля весов

Refs: 676104e
```

## Чек-лист перед коммитом

- [ ] Тип из таблицы, в нижнем регистре.
- [ ] Scope осмысленный и из списка проекта.
- [ ] Description на русском, повелительное наклонение, без точки.
- [ ] Body объясняет причину, а не пересказывает diff.
- [ ] Ломающее изменение помечено `!` и/или `BREAKING CHANGE:`.
- [ ] В сообщении нет PII, секретов и реальных резюме.
- [ ] Коммит содержит одно законченное изменение.
