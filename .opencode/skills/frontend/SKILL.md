# Frontend Tracing ATS

Скилл фиксирует текущий стек и визуальный язык приложения. Новые страницы,
блоки и контролы должны выглядеть и вести себя как существующие экраны, а не
как отдельный UI-кит.

## Эталонный коммит

Текущий стиль интерфейса зафиксирован в коммите:

```text
dda0e18 — fix(frontend): сократить список решений по отчёту
dda0e1884c46b606fa7332d6676f0231483d4c06
```

При добавлении новой страницы сверяйся с `frontend/` на этом коммите. Если стиль
сознательно меняется, обнови id эталонного коммита в этом скилле в том же
изменении.

## Источники истины

1. `contracts/openapi.yaml` — публичный REST-контракт и все DTO.
2. `AGENTS.md` — инварианты, границы сервисов, приватность.
3. `frontend/src/style.css` — токены, базовые классы, радиусы.
4. Существующие `views/` и `components/` — эталон текущего стиля.
5. Этот скилл — правила, как эти экраны устроены.

Если поля или эндпоинта нет в контракте, не выдумывай его. Меняй контракт в том
же изменении и перегенерируй клиент.

## Стек

| Слой | Технология |
|---|---|
| Фреймворк | Vue 3.5, Composition API, `<script setup lang="ts">` |
| Язык | TypeScript 5.9, strict, `noUnusedLocals` |
| Сборка | Vite 8 + `@vitejs/plugin-vue` |
| Роутинг | Vue Router 4.5, history mode |
| Стили | Tailwind CSS 4 через `@tailwindcss/vite`, CSS-first |
| Иконки | `@lucide/vue` |
| HTTP | axios + сгенерированный `typescript-axios` клиент |
| Markdown | `markdown-it` с `html: false` в `MarkdownText.vue` |
| Тесты | Vitest + `@vue/test-utils` + jsdom |

Нет shadcn-vue, reka-ui, CVA, Pinia, vee-validate, vue-sonner и `lucide-vue-next`.
Не добавляй их без отдельного решения и причины.

## Структура

```text
frontend/src/
├── App.vue                 # шапка, навигация, RouterView, ToastHost
├── main.ts
├── router/index.ts
├── api/
│   ├── index.ts            # axios, interceptors, экспорт api-клиентов
│   └── generated/          # генерация, не коммитится
├── components/             # доменные компоненты и общие примитивы
├── composables/useToast.ts
├── lib/
│   ├── format.ts           # даты, размеры, названия резюме, склонения
│   ├── labels.ts           # русские подписи enum
│   └── logger.ts
├── views/                  # страницы и сценарии
├── types.ts                # EditableRequirement и адаптеры
└── style.css               # токены и @layer components
```

Правила:

- `views` знают про API, роутер и сценарии; `components` получают данные через
  типизированные props/emits.
- Один компонент — один файл, `PascalCase.vue`.
- Форматирование и подписи — в `lib/`, не дублируй в шаблонах.
- Импорты внутри `src` — через `@/`.

## Текущий визуальный стиль

### Общий характер

Спокойный рабочий интерфейс HR: светлый фон, slate-текст, индиго-акцент,
белые карточки с тонкой рамкой и мягкой тенью. Никаких тяжёлых градиентов,
кроме логотипа; никаких пёстрых фонов и декоративных элементов.

Ключевой принцип: **меньше служебной информации**. В интерфейсе не показываем
ID, версии, названия моделей и промптов, бейджи PII/слепого режима, фразы про
LLM и аудит, технические подсказки вроде «поле появится после поддержки API».

### Токены

`style.css`:

- Фон страницы: `#f5f7fb` + радиальный индиго-градиент сверху слева.
- Тёмная тема: класс `dark` на `<html>`, переключатель в шапке, выбор хранится
  в `localStorage` (`tracing-ats-theme`). По умолчанию — светлая тема. Палитра
  Tailwind переопределяется под `.dark`, плюс отдельные правила для `.card`,
  `.input`, кнопок и модалок.
- Шрифт: `Inter, "Segoe UI", system-ui, sans-serif`.
- Радиусы через `@theme`: `lg 0.375rem`, `xl 0.5rem`, `2xl 0.625rem`,
  `3xl 0.75rem`. Углы намеренно острее стандартного Tailwind.
- Карточки: `rounded-2xl`, белый фон, `border-slate-200/80`, мягкая тень.
- Кнопки, поля, компактные блоки: `rounded-xl` / `rounded-lg`.
- Бейджи: pill `rounded-full`; статусы в таблицах и отчётах — `rounded-md`.

### Каркас страницы

- Контент: `mx-auto max-w-7xl px-4 py-8 sm:px-6`.
- Шапка: sticky, `border-b`, белый полупрозрачный фон, backdrop blur.
- Навигация: только «Вакансии» и «Резюме»; активный пункт — `bg-slate-100`.
- Вертикальные отступы страницы: `space-y-5` или `space-y-6`.
- Сетки: `gap-4` / `gap-5`.

Заголовок страницы-списка:

```html
<header class="flex flex-wrap items-end justify-between gap-4">
  <div>
    <p class="section-label">Рабочее пространство</p>
    <h1 class="mt-1 text-3xl font-semibold tracking-tight text-slate-900">Вакансии</h1>
    <p class="mt-1 text-sm text-slate-500">Короткое описание.</p>
  </div>
  <RouterLink class="btn-primary">Действие</RouterLink>
</header>
```

- `section-label` — маленький uppercase-лейбл.
- H1 — `text-3xl font-semibold tracking-tight`.
- Описание — `text-sm text-slate-500`.
- Основное действие — справа, `btn-primary`.

### Карточки списков

Вакансии и резюме — карточки, не таблицы:

- Сетка `grid gap-4 sm:grid-cols-2 xl:grid-cols-3`.
- Карточка: `card flex flex-col p-5`, hover `border-indigo-200 shadow-md`.
- Заголовок: `text-lg font-semibold`, ссылка с hover `text-indigo-600`.
- Теги: `badge-neutral` (тип, размер, дата, уровень, количество).
- Футер: `mt-auto border-t border-slate-100 pt-4`, дата слева, «Открыть →» справа.
- Удаление — `icon-btn` с `Trash2`, подтверждение через `ConfirmDialog`.
- Статус резюме — цветной `rounded-md` чип (`resumeStatusClass`).

### Детальная страница

Единый каркас для вакансии и резюме:

```html
<div class="grid gap-5 lg:grid-cols-[minmax(0,2fr)_minmax(0,1fr)] lg:items-start">
  <div class="space-y-5">карточка + текст</div>
  <aside class="lg:sticky lg:top-24">подбор справа</aside>
</div>
```

- Слева 2/3: карточка сущности, затем текст (markdown для вакансии,
  `whitespace-pre-wrap` для резюме).
- Справа 1/3: кандидаты/вакансии, sticky на desktop.
- В карточке сущности — только полезные поля: название, специализация, уровень,
  количество требований; без версий и технических метаданных.
- Действия: «Редактировать», раскрытие PII — в карточке текста.

### Формы и редакторы

- Формы — карточки `card p-5`, поля `label` + `input` / `select` / `textarea`.
- Двухколоночные поля: `grid gap-4 sm:grid-cols-2`.
- Подсказки — `hint`, только если они реально помогают; технические комментарии
  не писать.
- Длинные тексты (описание вакансии, текст резюме) — auto-grow textarea:
  `resize-none overflow-hidden`, высота по `scrollHeight`, без внутреннего
  скроллбара.
- Создание вакансии: карточка «Параметры» + карточка «Описание» + sticky-aside
  с итогом и кнопкой.
- Создание резюме: карточка-превью сверху, ниже текст и компактная загрузка.
  Максимум один файл; текст можно добавить вместе с файлом.
- Опыт в требованиях — числовое поле с шагом 1 год.
- Редактирование резюме — inline, на месте просмотра, не в модальном окне.
- Редактор вакансии: доска — основной режим, список — вторичный. На доске
  доступны все поля требования; добавление — внизу каждой колонки.
- Sticky-футер редактора: «Использовать как шаблон» слева как вторичная кнопка,
  «Удалить» и «Сохранить» справа.

### Кнопки

| Класс | Когда использовать |
|---|---|
| `btn-primary` | главное действие: сохранить, открыть, подобрать |
| `btn-accent` | акцентное создание (например, «Создать вакансию») |
| `btn-secondary` | вторичные действия, отмена, раскрытие PII |
| `btn-danger` | удаление |
| `btn-ghost` | малозаметные действия в панелях |
| `icon-btn` | иконка 36×36: удалить, свернуть, подробности |

Правила:

- На экране одна главная кнопка.
- «Использовать как шаблон» не должна выглядеть главной.
- Иконки Lucide размером 13–18, `gap-1.5`/`gap-2` до текста.
- Не использовать круглые кнопки, кроме бейджей и аватаров.

### Бейджи и статусы

- `badge-neutral` — нейтральные теги.
- `badge-success` — успех/готово.
- `badge-warning` — предупреждение/частично.
- `badge-info` — индиго-акцент.
- `badge-danger` — ошибка/дубликат.
- Статусы резюме и типы требований — короткие русские подписи из
  `lib/labels.ts`.
- Решение HR по отчёту — только «Собеседование» и «Отказ».

### Таблицы

- Контейнер `rounded-xl border border-slate-200 bg-white shadow-sm`.
- Заголовок `bg-slate-50 text-xs uppercase tracking-wide text-slate-500`.
- Строки `divide-y divide-slate-100`, ячейки `px-4 py-3`.
- Статусы — `rounded-md border px-2 py-1 text-xs font-medium`.
- Не использовать тяжёлые тени и `rounded-3xl` для таблиц.

### Модальные окна и уведомления

- Все модалки — через `AppModal` (`role="dialog"`, Escape, клик по backdrop).
- Подтверждения — `ConfirmDialog` (`danger` для удаления).
- Раскрытие PII — только `RevealPiiDialog` с причиной 3–512 символов.
- Тосты — `useToast` + `ToastHost`: success/error/info, 4.5 секунды.
- Не использовать `alert`, `confirm`, `window.prompt`.

### Пустые состояния и загрузка

- Пустое состояние: `card` с иконкой, заголовком, текстом и одной кнопкой.
- «Ничего не найдено» — отдельное состояние с кнопкой сброса фильтров.
- Загрузка — skeleton-блоки, повторяющие сетку/карточки, а не один спиннер.
- Долгие операции — inline-прогресс или spinner внутри кнопки.

### Типографика и текст

- Основной текст — `text-sm text-slate-600/700`.
- Метаданные — `text-xs text-slate-400/500`.
- Заголовки карточек — `text-base font-semibold`.
- Заголовки деталей — `text-2xl` или `text-3xl font-semibold tracking-tight`.
- Текст интерфейса — русский, короткий, без технического жаргона.
- Склоняй счётчики: `requirementsCount(count)`, `pluralizeRu`.
- Даты — `formatDate`, размеры — `formatBytes`, название резюме —
  `resumeDisplayTitle`.

## Текущие маршруты

| Путь | Экран |
|---|---|
| `/vacancies` | список вакансий |
| `/vacancies/new` | создание вакансии |
| `/vacancies/:id` | просмотр вакансии + автоподбор кандидатов |
| `/vacancies/:id/edit` | редактор требований |
| `/resumes` | список резюме |
| `/resumes/new` | добавление резюме |
| `/resumes/:id` | просмотр/редактирование резюме + подбор вакансий |
| `/dictionary` | словарь: очередь, навыки и генерация |
| `/applications/:id/report` | отчёт по отклику |
| `/resumes/:resumeId/vacancies/:vacancyId/report` | отчёт по паре |

Старые `/match`, `/analyses`, `/compare`, `/vacancies/:id/candidates`,
`/resumes/:id/text` — только редиректы.

### Словарь

- Три вкладки в порядке: «Навыки», «Генерация», «Очередь»; счётчики — в бейджах
  вкладок. По умолчанию открываются «Навыки».
- Очередь — карточки новых написаний с образцами и кнопками привязки/создания/отклонения.
- Навыки — поиск, фильтры по типу и статусу, карточки с алиасами и inline-формой
  добавления алиаса; создание навыка — через `AppModal`.
- Генерация — форма специальности и лимита, история черновиков карточками,
  активный черновик с чекбоксами навыков/алиасов и подтверждением.
- Статусы и типы показываются русскими подписями, без raw enum и model/prompt.

## Доменные правила в UI

1. **Один скор без вилки.** Не показывай `scoreLow/scoreHigh`, не делай
   переключатель «предварительный/итоговый». Показывай итоговый скор, если он
   есть, иначе предварительный.
2. **PII только после reveal.** До раскрытия в DOM нет имени, контактов, фото и
   других PII. Раскрытие — отдельное действие с причиной; после него не
   сохраняй PII в store/localStorage/URL.
3. **Человек решает.** Решение по отчёту — только HR, с комментарием. Не
   автоматизируй отказы и приглашения.
4. **Доказательства.** В отчёте — «требование → доказательство → пробел».
5. **Без служебной информации.** Не показывай ID, версии, model/prompt, бейджи
   PII, тексты про LLM/аудит, источник и историю навыка.
6. **Кандидаты вакансии** приходят из автоподбора по всем резюме. В вакансии
   нет загрузки резюме и выбора фазы.
7. **Шаблоны** не показываются в общем списке вакансий; доступны в фильтре и при
   создании вакансии.
8. **Резюме** добавляется только на странице резюме; удаление — с
   подтверждением.
9. **Сравнение текстов** живёт под таблицей требований в отчёте; отдельной
   страницы `/compare` нет. Раскрытие PII резюме — в блоке «Резюме».

## API и состояние

- Все запросы — через `src/api/index.ts`; в компонентах нет голого axios.
- Клиент генерируется из `contracts/openapi.yaml`; `src/api/generated` не
  коммитится.
- `npm run gen-api` вызывается в `predev`, `pretest`, `prebuild`.
- Ошибки — `apiErrorMessage(e)`, код конфликта — `apiErrorCode(e)`.
- Локальное состояние — `ref`/`computed`; глобального store нет.
- Долгие операции — polling с cleanup в `onBeforeUnmount`.
- Загрузка файлов — `ResumeUploader`: один файл, проверка расширения и размера,
  текст можно добавить вместе с файлом.

## Компоненты, которые переиспользуй

- `AppModal`, `ConfirmDialog`, `ToastHost`.
- `RevealPiiDialog` — причина раскрытия PII.
- `MarkdownText` — единственное место с `v-html`; `html: false` обязательно.
- `ResumeUploader` — загрузка файла/текста.
- `RequirementRow` / `RequirementBoard` / `RequirementDetails` — требования.
- `TextComparison` — сравнение текстов в отчёте.

## Тесты и проверки

- `cd frontend && npm test` — Vitest, jsdom.
- `cd frontend && npm run build` — `vue-tsc -b && vite build`.
- Тесты обязательны для критичных сценариев: PII reveal, скоры, фильтры,
  сохранение шаблона, удаление, решение по отчёту.
- Не коммить сгенерированный клиент.
- Не писать «готово», если проверки не запускались.

## Чего не делать

- Не добавлять shadcn-vue, CVA, Pinia и другие UI-библиотеки без решения.
- Не использовать `window.alert/confirm/prompt`.
- Не дублировать DTO и enum вручную.
- Не считать баллы и не смешивать Score_pre/Score_final.
- Не показывать вилку, ID, версии, model/prompt и служебные комментарии.
- Не класть PII в DOM/store/localStorage до reveal.
- Не делать новые страницы в другом визуальном стиле: сначала посмотри
  соседний экран и повтори его каркас, отступы, кнопки и типографику.

## Когда остановиться и спросить

- нужна новая зависимость или UI-кит;
- меняется контракт или добавляется эндпоинт;
- решение влияет на PII, слепой режим или скоринг;
- неясно, какой экран считать эталоном для нового сценария.
