# Отчёт о проделанной работе

## Когда применять
Только по явной просьбе пользователя ("сделай отчёт", "что ты сделал", "итоги"). Не создавай отчёт сам после каждой задачи.

## Куда сохранять
Каждый отчёт записывается отдельным файлом в `docs/reports/`. Создай каталог, если его нет:

```bash
mkdir -p docs/reports
```

Перед созданием файла найди номер последнего отчёта и увеличь его на единицу:

```bash
ls docs/reports 2>/dev/null | grep -E '^[0-9]{3}-' | sort | tail -1
```

Правила нумерации:
- имя файла — `docs/reports/NNN-<тема>.md`, где `NNN` — трёхзначный номер (`001`, `002`, …), тема — короткая латиница в kebab-case;
- если отчётов ещё нет, следующий номер — `001`;
- если последний файл `007-....md`, следующий — `008-....md`;
- номер не переиспользуется и существующие отчёты не перезаписываются;
- первая строка файла — заголовок `# Отчёт NNN — <тема>`;
- в ответе в чат укажи путь к созданному файлу и краткую выжимку.

## Источники фактов
Не пиши по памяти. Перед отчётом проверь реальное состояние:
- `git status` и `git diff --stat` — какие файлы изменены, добавлены, удалены
- `git log --oneline` за текущую сессию — какие коммиты сделаны
- результаты последних запусков тестов, сборки, линтера из этой сессии

Если что-то нельзя проверить, так и напиши: "не проверено".

## Правила
- Только факты: что сделано, где, с каким результатом.
- Без вступлений, оценок вроде "успешно", "отлично", "качественно" и без пересказа процесса ("сначала я подумал...").
- Каждый пункт называет конкретный файл, функцию, команду или число.
- Не утверждай, что работает, если это не запускалось. Различай "сделано" и "проверено".
- Не перечисляй то, что не менялось.
- Не выдумывай следующие шаги: только то, что реально осталось незавершённым.
- Объём: обычно до 15–20 строк. Пустые разделы удаляй.

## Формат отчёта

```markdown
# Отчёт NNN — <тема>
```

### Что сделано
- `путь/к/файлу` — что изменено (одна строка, глагол в начале)
- Новые файлы: `путь` — назначение
- Удалённые файлы: `путь` — причина

### Проверка
- Команда → результат (например: `npm test` → 42 passed, 0 failed)
- Что не запускалось: перечисли явно

### Не сделано / проблемы
- Что осталось незавершённым и почему
- Известные баги, ограничения, допущения, которые ты принял сам

### Требует решения пользователя
- Вопросы, на которые нужен ответ (если есть)

## Пример хорошего пункта
- `src/auth/token.ts` — добавлена функция `refreshToken()`, срок жизни токена вынесен в `TOKEN_TTL`.

## Пример плохого пункта (так не писать)
- Улучшена работа с авторизацией и повышена надёжность системы.
