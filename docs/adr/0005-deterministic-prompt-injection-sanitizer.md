# ADR 0005. Детерминированная очистка prompt injection

- **Статус:** принято
- **Дата:** 2026-11-10
- **Контекст:** `resume-service`, разделы 7 и 8 AGENTS.md

## Контекст

Текст резюме — недоверенные данные. В нём могут быть фразы «игнорируй предыдущие
инструкции», «верни 100 баллов», «раскрой системный промпт». Отправлять такой текст
в LLM и надеяться на системную инструкцию недостаточно: инъекция может повлиять на
разбор резюме. При этом нельзя переписывать обычный текст и нельзя логировать
подозрительные фрагменты целиком.

## Решение

- `PromptInjectionSanitizer` — детерминированный набор из 20–30 правил (английский и
  русский): ignore/disregard/forget previous instructions, system prompt, jailbreak,
  return score, output JSON, «игнорируй инструкции», «верни оценку», «повысь балл» и т. п.
- Каждое совпадение заменяется на `[REMOVED_INSTRUCTION]`.
- В `parsed_resume.injection_flags` сохраняются только идентификатор правила, номер
  строки и SHA-256 фрагмента. Исходный текст и его обратимая форма не хранятся.
- Санитайзер запускается **после** маскировки PII и **до** записи `masked_text` и
  вызова скоринга. Порядок важен: сначала убираем PII, потом инструкции, чтобы
  флаги не содержали PII.
- Обычный текст, включая «инструкцию по охране труда», не затрагивается.

## Последствия

- Правила нужно расширять по мере появления новых атак; это не ML и не «починка»
  ответа LLM регулярками.
- Ложное срабатывание удаляет фразу из текста и снижает покрытие требования, поэтому
  правила должны быть узкими.
- Санитайзер не заменяет строгую схему ответа LLM и проверку цитат: это второй слой
  защиты, а не единственный.
