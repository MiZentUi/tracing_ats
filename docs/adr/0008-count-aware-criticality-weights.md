# ADR 0008. Веса критичности с учётом размера групп

- **Статус:** принято
- **Дата:** 2026-11-14
- **Контекст:** `Wv^i` пока не зафиксирован в `rfc-scoring-model.md`;
  `CriticalityWeightPolicy` раньше не знал, сколько требований каждой
  критичности пришло в вакансии.

## Контекст

Если вес требования зависит только от критичности, группа из десяти `MUST`
получает в десять раз больший суммарный вес, чем группа из одного `MUST`.
Из-за этого один большой раздел требований может перевесить остальные,
даже если относительная важность критичности не менялась.

Нужно сохранить базовые веса групп, но дать политике возможность учитывать
их размер и позволить заменить подбор весов без правок калькулятора.

## Решение

1. `WeightPolicy.weight` принимает `counts: Mapping[int, int]` —
   распределение требований по критичности.
2. `CriticalityWeightPolicy` по умолчанию нормализует базовый вес требования
   на размер его группы:

   ```text
   Wv^i = base(criticality) / count(criticality)
   ```

   Суммарный вес группы остаётся равным `base(criticality)`.
3. Нормализацию можно отключить:

   ```python
   CriticalityWeightPolicy(normalize_by_counts=False)
   ```

4. Свой подбор весов можно передать callback-функцией:

   ```python
   CriticalityWeightPolicy(
       weight_fn=lambda criticality, counts: ...,
   )
   ```

   или реализовать собственный `WeightPolicy` с методом
   `weight(criticality, counts)`.
5. Критичность не вводит отдельный cap; веса остаются неотрицательными и
   входят в уже существующую нормализацию `R'` в калькуляторе.

## Последствия

- Большая группа требований больше не доминирует только за счёт количества.
- Пользователь может задать собственную формулу весов, включая зависимость
  от распределения критичностей.
- Изменение поведения весов фиксируется новой версией скоринга
  (`scoring-v6`, `grpc-scoring-service-v7`); старые запуски не пересчитываются.
- Формулы `R'` и `Score` не меняются.
